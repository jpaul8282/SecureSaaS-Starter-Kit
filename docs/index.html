Security & Data Privacy Standards

Cryptographic guarantees, key protection, and GDPR / CCPA user rights enforcement.

Data at Rest: AES-256-GCM

Local data persistence uses NIST-standard AES-256-GCM. Every record is encrypted with a unique 96-bit initialization vector (IV) generated by SecureRandom and protected by a 128-bit authentication tag, detecting any unauthorized bit flipping.

Data in Transit: TLS 1.3 Strict

All remote requests enforce TLS 1.3 with Perfect Forward Secrecy. Ciphers are constrained to TLS_AES_256_GCM_SHA384 and TLS_CHACHA20_POLY1305_SHA256. Certificate pinning eliminates risk from compromised public Certificate Authorities.

Hardware Security: Android StrongBox

Keys are generated within the tamper-resistant hardware security module (HSM) on supported Android devices. Private keys cannot be extracted via physical probing, debugging, or system rooting.

User Privacy: GDPR & CCPA

Zero-knowledge customer records, Article 20 JSON data portability export, Article 17 Right to Erasure with automated purge pipeline, and CCPA Do-Not-Sell opt-out switches built natively into the UI.

Frequently Asked Questions

Comprehensive troubleshooting and solutions for common Stripe integration and security configuration queries.

STRIPE INTEGRATION

Payment & Billing Queries

How do I switch BillingHub from Stripe Sandbox test mode to Live production mode?

To transition from test mode to live production processing, execute these three configuration updates:

  • Update Publishable Key: Replace your pk_test_... key in .env (and the AI Studio Secrets panel) with your verified Stripe live key pk_live_.... The Secrets Gradle Plugin automatically injects this into BuildConfig.STRIPE_PUBLISHABLE_KEY during compilation.
  • Configure Production Webhook Secret: Update STRIPE_WEBHOOK_SECRET with your live endpoint secret (starting with whsec_...) created in the Stripe Developer Dashboard under Webhooks > Add endpoint.
  • Map Production Price IDs: Ensure the recurring Price IDs configured in your subscription model match the live Price objects generated in your Stripe Product Catalog.
Security Rule: Never store or commit your Stripe Restricted Secret Key (rk_live_... or sk_live_...) on the Android mobile client. The Android app only ever receives the client-safe Publishable Key.
How are Stripe webhook signatures verified and replay attacks prevented?

BillingHub validates every inbound webhook notification using RFC 2104 compliant HMAC-SHA256 signatures:

  • Header Extraction: The receiver parses the Stripe-Signature header into timestamp (t=...) and signature scheme (v1=...).
  • Signature Computation: It builds the signed payload string timestamp + "." + rawBody and computes the HMAC-SHA256 hash using the shared STRIPE_WEBHOOK_SECRET.
  • Timing-Attack Safe Comparison: Signatures are compared using constant-time equality checks (MessageDigest.isEqual) to prevent timing side-channel attacks.
  • Tolerance Window: Requests with a timestamp older than 300 seconds (5 minutes) are rejected to eliminate replay attacks.
How does Strong Customer Authentication (SCA) & 3D Secure 2.0 work on Android?

For European PSD2 / SCA compliance and high-risk transactions requiring biometric or SMS one-time password verification:

  • When a PaymentIntent enters the requires_action state with use_stripe_sdk, the Android SDK natively presents the issuing bank's 3D Secure challenge sheet.
  • Sandbox test card 4000 0027 6000 3184 is pre-configured in BillingHub to simulate and test this exact challenge flow without real bank charges.
  • Upon completion, the listener receives the confirmed PaymentIntent and moves the subscription state machine to active without disrupting the user flow.
How does BillingHub handle failed subscription renewals and dunning grace periods?

When an existing card fails renewal (e.g., card expired, insufficient funds):

  • Stripe fires the invoice.payment_failed webhook event. BillingHub updates the subscription status to past_due.
  • A grace period banner appears in the dashboard inviting the user to update their payment method before service interruption.
  • Stripe Smart Retries algorithm attempts collection up to 4 times based on machine learning models. If all retries fail, customer.subscription.deleted downgrades the account to the Starter tier.
Are raw credit card numbers (PAN / CVC) ever stored or processed on the device?

Absolutely not. BillingHub employs zero-knowledge tokenization architecture:

  • Raw PAN, expiry, and CVC inputs are captured directly within isolated Stripe SDK UI fields and transmitted over TLS 1.3 straight to Stripe's certified PCI-DSS Level 1 tokenization vaults.
  • Neither application RAM, Room database, nor device flash storage ever receives or retains raw card numbers.
  • The app only stores the returned non-sensitive Stripe PaymentMethod token (pm_xxx), card brand, and masked last 4 digits (e.g. •••• 4242), keeping PCI compliance burden strictly at SAQ A-EP.
SECURITY & PRIVACY

Cryptographic & Compliance Queries

How does AES-256-GCM encryption protect cached data and tokens at rest?

Data at rest in BillingHub uses NIST-certified AES-256 in Galois/Counter Mode (GCM):

  • Authenticated Encryption (AEAD): Every ciphertext chunk is coupled with a 128-bit authentication tag. Any unauthorized bit flips or offline modification immediately invalidate the tag and abort decryption.
  • Unique IVs per Record: Every encryption pass generates a fresh 96-bit Initialization Vector using SecureRandom. IV reuse is cryptographically prohibited.
  • Envelope Encryption: Symmetric database encryption keys are themselves encrypted and protected by the master key residing in the Android Keystore.
What is the Android Keystore StrongBox HSM architecture and why is it tamper-resistant?

On supported devices (Android 9.0+), BillingHub requests keys configured with setIsStrongBoxBacked(true):

  • Dedicated Hardware Isolation: StrongBox operates on a physically isolated microprocessor with dedicated CPU, secure memory, and true hardware random number generator (TRNG), completely separated from the main Android Application Processor.
  • Root & Memory-Dump Immune: Even if an attacker obtains kernel root access or performs memory dumping on the device, cryptographic private key material cannot be extracted outside the hardware boundary.
  • Cryptographic Attestation: Keys can prove hardware provenance via Keymaster X.509 certificate chains signed directly by Google and OEM root authorities.
How does BillingHub enforce TLS 1.3 strict transit security and certificate pinning?

Network transit enforces zero cleartext and strict transport security:

  • Network Security Config: res/xml/network_security_config.xml explicitly sets cleartextTrafficPermitted="false".
  • TLS 1.3 Protocol & Ciphers: OkHttp is pinned strictly to TLS 1.3 with Perfect Forward Secrecy cipher suites (TLS_AES_256_GCM_SHA384 and TLS_CHACHA20_POLY1305_SHA256), eliminating obsolete ciphers and renegotiation vulnerabilities.
  • Public Key Pinning: Public key SHA-256 certificate pins are validated on all connections to api.stripe.com and billing endpoints, thwarting rogue CA interception and man-in-the-middle (MITM) attacks.
How do the GDPR Article 17 (Right to Erasure) and Article 20 (Data Portability) pipelines work?

Privacy regulations are directly operationalized via interactive tools in the app:

  • Article 20 Data Portability: Clicking Export Data (JSON) generates an unencrypted, standardized JSON archive including user profile, active subscription status, quota usage metrics, and payment transaction logs, downloadable to the user's device.
  • Article 17 Right to Erasure: Clicking Request Account & Data Deletion executes an irreversible purge pipeline: cancels recurring Stripe subscriptions, flushes Keystore keys, zeroes out database rows, and deletes cached local preferences.
  • CCPA Do-Not-Sell: A dedicated native switch immediately toggles off any external telemetry and diagnostic analytics sharing.
Why is .env and Secrets Gradle Plugin used instead of local.properties or hardcoded values?

Industry best practice and repository safety rules:

  • Zero Secret Leakage: Secrets are maintained in .env which is strictly listed in .gitignore, guaranteeing credentials are never committed to public or private Git repositories.
  • Secrets Gradle Plugin: At build time, the plugin parses .env and compiles the values into typed fields in BuildConfig (e.g. BuildConfig.STRIPE_PUBLISHABLE_KEY).
  • Container & CI Compatibility: The AI Studio Secrets panel provides runtime environment variable injection without relying on local machine filesystem paths.

PLAY CONSOLE WARNING 1

"Add a deobfuscation file associated with this App Bundle"

R8 shrinks and obfuscates class, field, and method names (e.g. com.example.BillingService becomes a.b.c) to reduce binary size and protect proprietary IP. Play Console requires mapping.txt to reconstruct human-readable crash and ANR reports.

PLAY CONSOLE WARNING 2

"This App Bundle contains native code, and you've not uploaded debug symbols"

The bundle includes native libraries (libandroidx.graphics.path.so and libdatastore_shared_counter.so across arm64-v8a, armeabi-v7a, x86, and x86_64). Unstripped debug symbols allow Play Console to symbolize C/C++ tombstone traces.

Step-by-Step Google Play Console Upload Instructions

  1. Navigate to App Bundle Explorer: Log into Google Play Console, open the BillingHub application, and click App bundle explorer in the left sidebar navigation under Release.
  2. Select App Bundle Version: Select VersionCode 6 (Version 6.0) from the bundle version dropdown or table.
  3. Open Downloads Tab: Click the Downloads tab on the right side of the screen.
  4. Upload Deobfuscation File: Under the Assets section, locate Deobfuscation file (or ReTrace mapping file). Click the upload arrow button and upload mapping.zip (or unzipped mapping.txt).
  5. Upload Native Debug Symbols: Under the Native debug symbols section, click the upload arrow button and upload native-debug-symbols.zip.
  6. Verify ANR & Crash Resolution: Under Quality > Android Vitals > Crashes and ANRs, all incoming crashes and ANR (Application Not Responding) traces will automatically be deobfuscated and displayed with exact file names and line numbers.
